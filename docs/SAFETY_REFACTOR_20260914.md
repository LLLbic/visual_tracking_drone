# 2026-09-14 安全控制重构：实现与验收边界

## 已实现

- 原悬停三秒自动交接禁用。本地起飞完成仍保持原位置，不能启动第二个键盘发送器。
- 键盘单一发送线程包含 BRAKING、MOVING、POSITION_HOLD。速度目标限变化率；松键先减速，测得水平/垂直速度均不大于0.10m/s且持续1秒后捕获位置，不随漂移更新保持点。
- 工程初始限值：水平加速度0.5m/s²，垂直0.3m/s²，偏航角加速度20°/s²。不是机型实飞标定值。
- 键盘按键唤醒不再突破配置发送频率；停止后重新开启使用新代次，旧包不能混入新会话。
- 本地起飞和键盘使用独立导航健康检查：各消息新鲜度、有限数值、RC数值范围、光流质量、ESTIMATOR_STATUS标志及位置/速度创新比值、测距范围。
- 飞行中光流归零、估计器异常或特定故障消息锁存导航故障。恢复一个好样本不会自动恢复控制。当前故障锁存在进程内保持到重启；重启仍默认安全锁存且所有TX关闭。
- 本地位置不连续性以位置-速度残差大于0.20m报警；这是启发式保护，不等于读取到了PX4内部重置计数。
- 全球位置消息不再覆盖本地速度；其他系统或非飞控组件不能覆盖控制遥测。
- 三类连续发送器共用SafetyGate原子发送边界，锁存完成后禁止后续包；UDP发送超时0.1秒。
- 请求LAND/RTL先撤销本地起飞任务，防止请求失败后旧任务继续争用。实体模式接管不会被自动撤销。
- 不修改PX4参数、RC覆盖或MANUAL_CONTROL，不自动ARM或切换Offboard。视觉跟踪TX仍关闭。

## 仍需验证，不能宣称完整实飞安全

ESTIMATOR_STATUS不是每轴光流融合拒绝状态，标准消息不能完整替代ULog内部EKF重置计数。
缺少消息将禁止电脑导航，不自动修改PX4或请求放宽门槛。光流质量非零不是定位准确保证。
健康异常停止Offboard发送可能触发PX4已有失联策略；本次不改变该策略，也不保证能安全悬停/降落。
安全门只管本地程序，不撤回已进网络的包，不控制QGC和遥控器。实体遥控优先取决于实际飞控/数传链路，不能由网页保证。
本地起飞和键盘之间的自动无缝交接仍未开放，不能把当前版本作为完整自动跟踪飞行系统使用。
首次验收应使用仿真和拆桨环境，覆盖消息丢失、RC退出、网页失焦、定位跳变、LAND拒绝、服务退出。
