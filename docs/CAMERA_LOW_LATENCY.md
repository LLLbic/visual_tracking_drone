# D7 相机低延迟配置与验证（2026-09-11）

## 实际完成

相机地址为 `192.168.111.11`，工作站使用 `channel=1&stream=1` 子码流。

| 项目 | 调整前 | 调整后 / 实测 |
| --- | --- | --- |
| 子码流编码 | H.265 | H.264 |
| 分辨率 | 640×360 | 640×360，保持不变 |
| 帧率 | 5 FPS | 15 FPS |
| I帧间隔 | 配置 GOP=2（秒） | 配置 GOP=1（秒），实测每15帧一个I帧 |
| B帧 | 0 | 0 |
| 子码流码率设置 | VBR / 53 kb/s | CBR / 512 kb/s（配置目标，不是测得的链路占用） |
| 智能编码 | SmartH264=false，SmartH264Plus=0 | 保持关闭 |
| 独立“发送平滑”开关 | 未发现 | 未修改、未宣称已关闭 |
| 电脑解码 | hevc_cuvid | h264_cuvid / NVIDIA NVDEC |

注意：设备配置中的 `QVGA` 名称不能用于推断实际像素尺寸；RTSP实测为640×360。

## 固件限制与影响范围

- 单独把子码流的Compression改成H.264，设备会将其回退到主码流的H.265。
- 同时把主、子码流Compression设为H.264后保存成功；主码流的分辨率、5 FPS和其他设置保持不变。
- 相机返回603表示需要重启设备。已仅向相机的DVRIP服务发送一次重启，让编码格式生效。未重启飞控、无人机或数传，未修改PX4参数。
- 相机网络配置未改。`NetWork.NetCommon.TransferPlan=Quality` 是传输策略字段，不能未经验证就当作“发送平滑”开关。
- 原浏览器配置页面要求旧版播放插件，因此使用相机配置协议完成读取、备份和设置，没有安装该插件或关闭浏览器安全保护。

## 工作站改动

- 配置切换为H.264硬件解码，继续使用UDP与100 ms的有限乱序等待。
- FFmpeg使用RTSP的 `-timeout` 设置2.5秒socket I/O超时，而非只设置通用 `-rw_timeout`。
- rawvideo输出设为 `-threads:v 1`；软件解码回退路径也禁用帧线程队列。
- 采集与YOLO分线程、只保留最新帧；没有用补帧或 `-r 15` 伪造源帧率。
- 前端现在分别显示“采集 / 处理 / 输出”FPS，避免把处理速率标成源帧率。
- FRUC仍关闭。飞控控制逻辑、保护条件和端口配置未修改；验证期间键盘TX、Offboard设定值和真实动作计数均为0。

## 备份与重复配置

相机配置备份在本机 `.runtime` 中（已被Git忽略）：

- `camera-encoding-before-20260911.json`：原始简化编码参数。
- `camera-encoding-apply-20260911.json`：第一次修改之前，包括AVEnc及网络配置的只读备份。
- `camera-encoding-h264-20260911.json`：同步主、子码流编码前的备份。
- 同名 `.after.json`：对应的写入返回码与参数回读。

`tools/camera_encoding.py` 默认只读取和备份。写入必须明确加 `--apply-h264-substream`；
需要同步主码流编码时再加 `--sync-main-codec`。备份使用独占创建，不覆盖已有备份。
脚本不会自动重启设备，也不访问MAVLink或飞控。密码可通过 `CAMERA_PASSWORD` 环境变量传入，不写进脚本。

```powershell
# 只读；每次使用新的备份文件名
.\.venv\Scripts\python.exe tools\camera_encoding.py --host 192.168.111.11 --backup .runtime\camera-inspection-new.json
```

协议参考：[OpenIPC python-dvr](https://github.com/OpenIPC/python-dvr)。

## 验收边界

已对重启后的实际UDP码流检查：H.264、15 FPS、无B帧；连续6秒的90帧中，关键帧索引为0、15、30、45、60、75。
工作站启动后采集、处理与输出约15 FPS，模型就绪，网页画面正常，观察期间重连计数为0。

这些结果**不等于已测得端到端延迟低于1秒**。相机画面上的OSD时间未与电脑同步，网页的
`age_seconds` 也只是最后处理帧的新鲜度，不能用来代表曝光到屏幕的延迟。
应在地面、TX关闭时，用另一台设备同时拍到真实动作/计时器与电脑显示画面，测量时间差。
测试原生RTSP与工作站时尽量逐一拉流，避免多个客户端干扰对比。
