# 本地起飞到键盘控制交接

最新项目配置启用独立的 [纯位置起飞/悬停恢复基线](FIXED_HOVER_BASELINE_20260914.md)。
该模式依赖实际收到的 PX4 定位有效输出；可选遥测缺失仍明确显示为未验证，已观测故障仍阻断。
下文详细 EKF 门槛适用于 `navigation_profile = "detailed"` 与后续交接研究，不再作为基础起飞的全部必需项。
键盘交接仍关闭，基础模式禁止启用交接；本说明不代表实飞通过。

## 当前阶段：仅起飞与悬停，暂不交接键盘

项目配置 `local_offboard_takeoff.keyboard_handoff_enabled = false`，缺省值同样为 false。
该选项在服务构造时固定，不能在飞行中通过网页开启。更新代码需在确认落地、
DISARM、实体急停打开后另行重启生效；本次代码修改没有重启服务或发送飞行指令。

- 从起飞/悬停检查中移出**交接专属的光流连续 3 秒、15 个不同样本要求**。
- 起飞/悬停不等待网页前台、松键、键盘授权或交接计时；前后端均拒绝键盘交接。
- 到高后原发送器继续发送启动时的 x/y/yaw 与最终 z 目标，速度前馈为零，
  不启动速度发送器、不重捕获漂移后的位置、不自动交接。
- 保留真实光流来源与新鲜度、定位/融合/创新检验、坐标重置、地面/ARM/RC状态、
  高度和姿态限值、超时及遥控器接管保护。位置稳定性仍用于确认悬停完成。

这不是“降低定位要求后强行放飞”。当前缺少可信融合/重置遥测适配，光流控制源也待核对；
这些问题仍阻止定点起飞。离线测试通过不能代替传感器验证或实飞验收。
下方显式键盘交接设计只适用于后续独立验证并明确启用该功能的版本。

## 2026-09-14 最新实现：单一轨迹与显式授权

事故日志与最新链路瓶颈、后续增补见 [光流与交接复核](FLOW_HANDOFF_REVIEW_20260914.md)。

本节取代下方历史设计。程序已实现并通过离线回归，不代表实飞安全验收。
本次未重启在线服务，未向无人机发送ARM、模式切换、起飞或键盘指令。

### 当前部署阻断项

现有 `PassiveMavlinkReceiver` 只接入常规估计器状态、光流质量、位置、RC等消息，
**尚未接入可信的光流融合/创新拒绝状态及完整估计器重置计数。**
新增字段默认均为缺失，不从质量非零、位置连续或心跳正常推断融合有效。
因此，新代码加载后，缺少重置证据会拒绝本地Offboard起飞预发送；
缺少光流融合证据会拒绝键盘授权。这是刻意的保护，不是可以绕过的提示。
本功能目前不能宣称已在这台无人机上完成可飞验证。

可信遥测适配层未来必须从当前飞控实际提供的详细估计器数据填充：

- `estimator_reset_signature`：同一估计器的 `(primary_instance, xy_reset, vxy_reset, z_reset, vz_reset, heading_reset)` 六项真实计数/实例编号。
- `last_reset_evidence_monotonic`：收到上述真实证据时的本机单调时钟；重放旧数据不得刷新。
- `flow_fusion_active`：当前选中估计器实际启用了光流融合。
- `flow_innovation_rejected`：光流创新是否被拒绝；必须明确为False。
- `flow_fusion_instance`：必须与主估计器实例一致。
- `flow_innovation_x_ratio` / `flow_innovation_y_ratio`：真实光流创新检验比，均为有效有限值且不超过1。
- `estimator_dead_reckoning`：必须明确为False，不能用质量高替代。
- `last_flow_fusion_monotonic`：收到真实融合证据时的本机单调时钟。

不能将不同实例的数据混在一起，不能用地面网页填写、历史ULog、
`ESTIMATOR_STATUS`通用有效位、非零光流质量或单独的ODOMETRY重置计数替代完整证据。
无相关实时数据出口时，必须保持禁止授权；本次没有修改PX4固件或任何参数来伪造支持。

### 控制结构

`LocalOffboardTakeoffCoordinator` 始终拥有同一个定频循环、套接字和发送权。
从悬停开始，`SmoothHandoff.step()`统一生成 `LOCAL_NED` 位置、速度前馈及航向目标。
HOLDING、键盘待命、移动、减速、位置保持均使用同一个消息格式与发送器。
按下授权按钮只生成本页会话令牌，不发送包，不启动线程，不停止悬停发送器。
授权前后首个目标完全相同，速度前馈从零开始；不是两个控制器互相切换。

```text
本地起飞 → 原目标悬停 → 持续检查 → 用户授权 → 松键确认 → 键盘待命
                               ↑                         ↓
                          重新人工授权 ← 减速保持 ← 松键/撤权/失焦
                                                         ↑
                         键盘改变期望速度 → 限加速度轨迹运动

遥控器退出Offboard / 定位故障 / 坐标重置 → 本次会话终止，不自动恢复
```

### 授权门槛（全部同时成立）

下列数字是保守工程初值，不是已经验证的实飞参数。

| 检查 | 门槛 |
| --- | --- |
| 水平位置误差 | 不超过0.15 m，相对原悬停目标，而非重新捕获当前漂移位置 |
| 高度误差 | 不超过0.15 m |
| 水平速度模长 | 不超过0.08 m/s |
| 垂直速度绝对值 | 不超过0.10 m/s |
| Roll/Pitch | 不超过5° |
| 连续稳定 | 至少3 s，至少15个按飞控源时间戳去重的位置样本，观测间隔不超过0.25 s；重复包不刷新样本新鲜度 |
| 估计器 | 姿态、水平位置/速度、垂直速度有效，垂直位置有效，位置/速度创新检验通过 |
| 光流 | 指定来源原始质量至少100，连续良好3 s且至少15个不同样本；融合启用、X/Y创新检验通过且未拒绝、非纯推算、实例一致；详细证据不超过0.5 s |
| 坐标系 | 起飞前记录真实重置计数；全流程任何计数或主实例变化都终止本次任务 |
| 其他遥测 | 心跳、姿态、RC、本地位置、落地状态、估计器、光流、有效对地测距均须新鲜 |
| 飞控与实体遥控 | ARMED、IN_AIR、实际模式OFFBOARD、CH8选择Offboard、CH6未触发 |
| 网页 | 当前页前台、已勾选现场确认、输入报告不超过0.4 s、全部控制键已松开 |
| 互斥 | 未锁存、路由正常、其他起飞流程/地面测试流/旧键盘发送器均关闭 |

W和S等相反按键同时按住不算“全部松开”，即使合成轴值为零。
计时完成只允许手动授权，不会自动开启控制。实际位置、速度和样本数在页面显示。

### 轨迹与边界

- W/S为前后、A/D为左右；按实时航向把机体期望速度转换到同一个LOCAL_NED坐标系。
- Shift/Alt为升降速度，不是电机油门；Q/E改变期望偏航速率。
- 水平速度上限0.25 m/s，垂直0.20 m/s，偏航10°/s；斜向运动不叠加突破水平上限。
- 水平加速度限制0.40 m/s²，垂直0.30 m/s²，偏航加速度20°/s²。
- 位置用连续受限速度的梯形积分更新，速度作为前馈发送；航向同样限速且处理角度环绕。
- 预发送、爬升、悬停、键盘全程使用相同LOCAL_NED位置/速度前馈/yaw掩码；循环卡顿超过250 ms禁止补发追赶，原任务不可自动恢复。
- 目标与实际水平偏差软限制0.20 m、硬限制0.45 m；垂直软限制0.15 m、硬限制0.30 m。
- 偏航目标偏差软限制15°、硬限制30°，飞机没跟上时不无限累积角度目标。
- 软边界预留制动距离，移除继续向外的速度，仍允许反向退回。硬边界在发送前检查，越界拒发并终止会话。
- 沿用以起飞点为中心的水平范围（默认半径1 m）；键盘高度限制在起飞基准上方1–3 m，降落必须用LAND流程。
- 松键后是受限减速，不是瞬间停机；减速完成保持轨迹终点，不把当前漂移位置不断重设为目标。

### 异常与人工接管

1. 失焦、关闭标签页、输入中断、撤销授权：清除授权，期望速度归零，由原轨迹限加速度减速后保持。重新聚焦不会自动恢复，需重新满足稳定条件并手动授权。
2. 估计器重置、定位失效、详细健康证据过期、严重目标偏差、发送故障或授权后循环停顿：立即终止本次本地控制会话，不沿用旧坐标、不补发累积目标、不自动重启或重新ARM。
3. 收到CH6急停、CH8退出或实际模式LAND/POSCTL/RTL等非Offboard遥测：停止本地设定值，不抢回模式，不发送抵消飞手操作的命令。
4. 用户LAND、RTL、安全处置锁存：仍走已有统一退出流程，先撤销本地控制；安全处置不是空中强制停桨。

电脑停止发送**不等于无人机立刻停止运动**。实际后续行为依赖现有PX4 Offboard失联处置、定位和遥控链路。
本程序不修改相关参数；若定位失效，不能承诺Position或软件定点保持能够止漂。
实体接管也是以实际链路及收到的状态为准，不是电脑软件可以保证的零延迟硬件抢占。
室内不可把RTL作为唯一后备手段，不能用数秒延迟的视频代替定位闭环。

## 以下为已停用的旧设计，仅保留历史说明

本地 Offboard 起飞完成悬停验证后，继续保持目标位置，并连续计时 3 秒。
高度或垂直速度离开原有悬停容差时重新计时。

交接要求：ARMED、IN_AIR、Offboard、CH6 未触发、CH8 仍选择 Offboard、
锁存未触发、遥测/位置有效，且网页在前台并勾选现场确认。
网页每 250 ms 报告前台就绪；最后一次报告超过 1 秒则暂不交接。

起飞线程先发送最后一个位置保持包，启动键盘零速度发送器。
确认首包已发送后，将状态改为 KEYBOARD_CONTROL 并停止位置发送。
发送器启动失败时继续位置保持并显示原因；不启动第二个起飞流程。
交接后的首个有效网页输入必须是所有轴归零，旧按键状态清除，持续按住的
键盘自动重复事件不会恢复旧指令。松键再按后才接受新的方向控制。

交接后沿用键盘输入看门狗及实体开关检查。零速度是速度目标，不是固定
原位置的保证；位置控制已交给飞控速度控制环。该流程只适用于本地
Offboard 起飞，PX4 原生起飞流程不自动交接。

验证采用模拟时钟、模拟遥测和捕获套接字，覆盖三秒计时、稳定性重置、
失败继续保持、飞手接管取消、首包归零和松键门槛；不代表实飞验收。
